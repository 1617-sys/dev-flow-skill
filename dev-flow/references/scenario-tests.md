# dev-flow 场景验证矩阵

> 仅在创建、升级或回归验证 Skill 时读取。普通开发任务不得加载本文件。

## 基线失败模式（RED）

v1 与两轮外部评审已经暴露以下失败：风险与 OpenSpec 绑定、按路径或文件数机械升级、stable 新增功能一律写规格、任意三次失败就暂停、把计划模式误当跨平台只读保证，以及可能擅自 stash 用户改动。最小 Skill 必须直接关闭这些缺口。

## 分类与门禁

| # | 请求与条件 | 风险档 | OpenSpec | 关键动作 |
|---|---|---|---|---|
| 1 | 移动端登录按钮改为全宽 | Quick | 否 | 直接修改；必须目视 |
| 2 | 恢复搜索去重，限于搜索功能及相邻测试 | Quick | 否 | 先建立失败基线再修复 |
| 3 | 恢复搜索去重，根因在共享缓存或跨模块查询 | Standard | 否 | 短计划；更广回归测试 |
| 4 | 修复权限绕过，恢复既有权限规范 | Strict | 否 | 只读门禁；负向权限测试 |
| 5 | 改变权限规则，即使新增测试 | Strict | 是 | 只读门禁；OpenSpec |
| 6 | stable 项目修改默认排序 | Strict | 是 | OpenSpec；兼容性验证 |
| 7 | stable 项目新增局部、直观、可逆的面板折叠 | Standard | 否 | 代码与测试记录行为 |
| 8 | stable 项目新增长期能力，含非显然业务约束，但不触碰 strict 硬触发 | Standard | 是 | OpenSpec 记录原因与约束 |
| 9 | prototype 项目新增可撤销筛选交互 | Standard | 否 | 回归与 UI 验证 |
| 10 | 修改 CSV 导出字段 | Strict | 是 | 兼容性与旧数据验证 |
| 11 | 行为不变的跨模块重构 | Standard | 否 | 相关套件验证 |
| 12 | 只修改 `auth/` 中的注释 | Quick | 否 | 路径只触发调查，不替代语义 |
| 13 | 调查后发现需要 schema migration | Strict | 是 | 首次写入前升级并暂停 |
| 14 | 生命周期未知且会改变 OpenSpec 结论 | 未定 | 未定 | 集中询问一次；继续只读调查 |
| 15 | 用户要求 Quick 删除生产数据 | Strict 安全底线 | 依语义判断 | 授权、备份、恢复和完整性检查不可降级 |
| 16 | 平台不能提供已验证只读能力 | Strict | 依语义判断 | 暂停并通知用户，不开始修改 |

## 失败与额度

| # | 验证轨迹 | 期望 |
|---|---|---|
| 17 | 编译失败 → 编译通过但测试失败 → 测试通过但 lint 失败 | 持续收敛，继续 |
| 18 | 修 lint 后测试重新失败，并在两者之间往返 | 振荡；累计无进展失败 |
| 19 | 相同失败特征连续三次，范围和证据均未变化 | 暂停；报告证据；不自动换模型 |
